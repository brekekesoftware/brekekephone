# Brekeke Phone 2.18.0 — what is new and what changed since 2.17.22

This list shows what a user or an admin will notice after updating from 2.17.22 to 2.18.0.
Each item says where it applies, how the app worked before, how it works now, and a simple way to try it.

Words used below:

- **Phone system**: the Brekeke PBX the app signs in to.
- **Admin**: the person who manages the phone system. Some items are set up by the admin; users only see the result.
- **Chat (UC)**: the Brekeke chat service that the app can use besides calls.
- **Phone slot**: a PBX user can have more than one phone (Phone 1, Phone 2, …). Each app uses one slot, chosen in the account settings.
- **Two-step sign-in**: the phone system can ask for an extra code after the password (admin setting `webphone.pal.mfa`).

## 1. Sign-in link

A sign-in link is a link the admin sends to a user, for example by mail.
Tapping it opens the app, fills in the account and signs in.

### A link without the real password

- Where: all (iPhone, Android, web)
- Before: the link had to contain the user's real password, readable by anyone who saw the link.
- After: the link can carry a coded form of the password (field `pwhash`) instead. The app signs in to calls and chat with it, and the real password is not in the link. If a link has both, the coded one is used.
- How to try: open a link with `pwhash` and no `password`: the user is signed in, and calls and chat work.

### A wrong or old coded password

- Where: all
- Before: not available.
- After: if the phone system refuses the coded password, the app does not add the account and says "This link has expired. Ask for a new link."
- How to try: open a link with a wrong `pwhash` for a user not yet in the app: the message shows and the account list stays the same.

### A newer link for the same user

- Where: all
- Before: not available.
- After: opening a newer link for a user already in the app replaces the saved password and signs in again. A link with a plain password replaces a saved coded one.
- How to try: open a link, then a link with a different `pwhash` for the same user: the app signs in again with the new one.

### A link fixes a wrong saved password

- Where: all
- Before: if the saved password was wrong, opening a link with the right password did not replace it, so sign-in kept failing.
- After: a link with a different password replaces the saved one and signs in again.
- How to try: save the account with a wrong password, then open a link with the right one: sign-in works.

### Account settings of a link account

- Where: all
- Before: not available.
- After: for an account added by a coded-password link, the password box is empty, shows the hint "Set a password", and "Signed in by link" is written under it. The user can save the account without typing a password.
- How to try: open the settings of that account: both texts show, and Save works with the empty box.

### More settings in the link

- Where: all
- Before: not available.
- After: the link can also set three account settings:
  - `turn=1` or `turn=0`: turns "USE TURN AUTOMATICALLY" on or off (see section 2).
  - `uc=1` or `uc=0`: turns chat (UC) on or off.
  - `parks=701:Sales,702:Support`: sets the park numbers (numbers used to park and pick up calls) with their names. `parks=` with nothing clears them.

  If the link does not have one of these fields, the saved setting stays. A wrong value is ignored.

- How to try: open links with each field and check the account settings.

### A link with another phone slot

- Where: all
- Before: if the user was already in the app and the link chose another phone slot (field `phone_idx`), calls kept ringing on the old slot.
- After: the app moves to the new slot. Calls ring on the new slot, and the old slot stops getting this app's calls.
- How to try: signed in as Phone 1, open a link with `phone_idx=2`, call Phone 2: the app rings.

## 2. TURN

TURN is a relay server that helps calls connect when the network blocks direct sound (for example some hotel or office Wi-Fi).
The admin sets the phone system's TURN server in the settings `webphone.turn.server`, `webphone.turn.username` and `webphone.turn.credential`.

### The TURN setting

- Where: all
- Before: the account setting was called "TURN" and was off by default. Turning it on added a TURN server built into the app. The phone system's TURN server was always used when the admin had set one.
- After: the setting is called "USE TURN AUTOMATICALLY" and is on by default, also for accounts saved before the update. On: the phone system's TURN server is used. Off: no TURN server is used. The TURN server built into the app is removed.
- How to try: add a new account: the setting is on. With the admin's TURN server set, call from a network that blocks direct sound: both sides hear each other.

### Changing TURN by a link

- Where: all
- Before: not available.
- After: when a sign-in link changes this setting for the account that is signed in, the app reconnects at once so the next call uses the new setting.
- How to try: while signed in, open a link with `turn=0`: the app reconnects; the next call uses no TURN.

## 3. AIPhone nurse call (admin)

AIPhone is a nurse call system for hospitals. During a call, the app can show a web page from the phone system in the call screen (the caller picture page).

### Turning nurse call on

- Where: iPhone, Android
- Before: not available.
- After: the admin turns it on for a user with the user setting `aiphone.nursecall.enable=true`. The app reads it at sign-in. The web phone ignores it.
- How to try: set it, sign in on the app: nurse call is on. Sign in on the web phone: nothing changes.

### Call details sent to the page

- Where: iPhone, Android
- Before: not available.
- After: when a nurse call comes in with call details from the phone system, the app gives the details to the caller picture page once per call, after the page has loaded. Calls the user makes do not do this.
- How to try: receive a nurse call: the page shows the details once. Make a call: the page gets nothing.

### Lock screen

- Where: Android
- Before: not available.
- After: the same works on the full-screen incoming call screen, for example when the phone is locked.
- How to try: lock the phone and receive a nurse call: the page shows the details.

## 4. Save web page messages to the debug log

The debug log is a file the user can share with support (Settings → Debug).

- Where: iPhone, Android
- Before: not available.
- After: Settings → Debug has a new switch "CAPTURE WEBVIEW LOG" ("Also capture messages from web pages"). It is off by default and can only be turned on when "CAPTURE ALL DEBUG LOG" is on. Messages and errors from web pages inside the app (caller picture pages and custom pages) are then saved in the debug log, so support can see why a page fails.
- How to try: turn both switches on, open a custom page, share the debug log: the page's messages are in it. Turn "CAPTURE ALL DEBUG LOG" off: the new switch is greyed out.

## 5. Clear app cache

The app keeps copies of caller pictures, images and web pages to load them faster.

- Where: iPhone, Android
- Before: not available.
- After: Settings → Debug has "CLEAR APP CACHE" ("Clear cached avatars, images and web pages"). It asks first. When done, it says "Please close the app and open it again to finish clearing the cache." Users may need to sign in again on custom pages.
- How to try: tap it, confirm, close and reopen the app: pictures load again from the phone system.

## 6. Calls and network

### A call survives a network drop

- Where: all
- Before: a call could end when Wi-Fi dropped for a moment, or when the phone moved between Wi-Fi and mobile data.
- After: the call stays on, and sound comes back when the network returns.
- How to try: in a call, turn Wi-Fi off (mobile data on), then on again: the call continues and both sides hear each other.

### Faster reconnect

- Where: all
- Before: after the network came back, the app waited for its next retry before it reconnected.
- After: the app reconnects right away when the network comes back or changes (for example Wi-Fi to mobile data).
- How to try: turn airplane mode on, then off: the app shows connected within a few seconds.

### A stuck call after hold

- Where: all
- Before: in a rare case (the phone system answers a hold or resume with "ringing"), the call stayed in a broken state.
- After: the call ends cleanly.
- How to try: hard to try by hand; needs a phone system test setup.

### Answering with no connection

- Where: all
- Before: answering a ringing call after the connection to the phone system was already lost gave a call with no sound.
- After: the call ends instead.
- How to try: hard to try by hand; needs a phone system test setup.

### Video call on hold

- Where: Android
- Before: a video call on hold showed a loading circle on the video.
- After: no loading circle while on hold.
- How to try: in a video call, tap Hold: no loading circle.

## 7. Sign-in

### No repeated tries after a wrong password

- Where: iPhone, web
- Before: after the phone system refused the password, the app could keep trying again. Repeated wrong tries can make the phone system block the user.
- After: the app tries once and shows the error. It tries again only when the user taps Reconnect or changes the password.
- How to try: sign in with a wrong password: one error, and the phone system log shows only one try.

### The wrong-password error stays

- Where: all
- Before: the wrong-password error could disappear when the network came back or the app was reopened, and the app tried again.
- After: the error stays, and the app does not try again by itself.
- How to try: wrong password, then airplane mode on and off, then close and reopen the app: the error is still shown.

### No false "logged in from another location"

- Where: all
- Before: a short network drop during sign-in could show "Logged in from another location as the same phone" and stop the account, though no other phone had signed in.
- After: the app ignores this case and stays signed in.
- How to try: turn Wi-Fi off and on while the app signs in: it stays signed in with no such message.

### Network drop during two-step sign-in

- Where: all
- Before: if the network dropped while the app was starting the two-step sign-in, the sign-in was lost.
- After: the sign-in is kept.
- How to try: user with two-step sign-in; turn the network off and on while the code step starts: the user can still finish.

### One code for calls and chat

- Where: all
- Before: with two-step sign-in, chat (UC) could ask for a second code after the phone system's code.
- After: the code is asked only once; chat uses the phone system's sign-in and connects by itself.
- How to try: user with two-step sign-in and chat on: enter one code; chat connects with no second code.

### Chat stops when it cannot start two-step sign-in

- Where: all
- Before: not available.
- After: if the chat service says it cannot start the two-step sign-in, chat stops trying and waits until the user taps Reconnect. This keeps the user from being blocked.
- How to try: needs a chat server test setup: chat shows not connected; one Reconnect tap gives one new try.

## 8. More than one account, notifications and chat

The app can keep several accounts, but only one is signed in at a time.

### Another account's call during a call

- Where: Android
- Before: during a call, a call to the user's other account opened its incoming call screen over the current call.
- After: the current call screen stays.
- How to try: in a call on account A, call account B: the call screen does not change.

### Another account's notification during a call

- Where: Android
- Before: during a call, tapping a notification for another account left the call screen.
- After: the call screen stays.
- How to try: in a call on account A, tap a notification for account B: still on the call.

### Chat notifications with only the message text

- Where: Android
- Before: when the chat notification from the phone system carried only the message text (no sender or other details), no notification was shown.
- After: a notification shows for these messages too.
- How to try: needs a test message with only the text: a notification shows.

### Chat tap while a call rings

- Where: Android
- Before: tapping another account's chat notification while a call was ringing did nothing at first, but switched the account later, when the call ended.
- After: no account switch after the call.
- How to try: while a call rings, tap another account's chat notification, then end the call: still on the same account.

### Chat notification with no account

- Where: iPhone, Android
- Before: a chat notification that did not say which account it was for could switch to another account.
- After: the app stays on the account that is signed in.
- How to try: needs a test message without an account: no account switch.

### Chat notification stays until opened

- Where: Android
- Before: tapping a chat notification while the app was starting could remove the notification without opening the chat.
- After: the notification stays until the chat opens.
- How to try: close the app, tap a chat notification: the chat opens.

## 9. Fallback local connection (LPC)

LPC lets the phone get calls over the office Wi-Fi without the internet push service (Apple or Google).
The admin sets LPC up on the phone system. With `webphone.lpc.pn=false`, the phone system delivers calls to a closed app only by LPC.

### Suggest turning LPC on

- Where: Android
- Before: not available.
- After: if the phone system delivers calls only by LPC, and push notification is on but LPC is off, the app shows "Fallback local connection" with ENABLE and DISMISS.
- How to try: on such a phone system, sign in with LPC off: the message shows; ENABLE turns LPC on.

### Warning before turning LPC off

- Where: Android
- Before: on such a phone system, turning LPC off took effect at once, with no warning.
- After: a "Warning" asks first: "Without LPC, this phone may miss calls while the app is closed." with TURN OFF.
- How to try: turn LPC off: the warning shows; cancel keeps it on.

### More than 10 office Wi-Fi networks

- Where: iPhone
- Before: the admin lists the office Wi-Fi networks for LPC in the phone system setting `webphone.lpc.wifi`. iPhone LPC works only on those networks. With more than 10 names in the list, iPhone refused the whole LPC setup, so a closed app got no calls by LPC.
- After: the app uses the first 10 names, and LPC works on them.
- How to try: list 11 or more Wi-Fi names, close the app, call it on one of the first 10 networks: the call arrives.

## 10. Web phone (in a browser)

### "Open in app" question on a phone

- Where: web on a mobile browser
- Before: the web phone asked "OPEN IN APP" or "OPEN IN BROWSER", but started signing in before the user answered.
- After: it waits for the answer first.
- How to try: open the web phone on a mobile browser: nothing signs in until a button is tapped.

### Blocked microphone

- Where: web
- Before: if the browser blocked the microphone, the call hung on "Connecting..." and the app dialed again 3 seconds later.
- After: the app shows a microphone error and ends the call. It does not dial again.
- How to try: block the microphone in the browser and make a call: the error shows and the call ends.

### Calls with no sound

- Where: web
- Before: on some networks, an answered call had no sound.
- After: fixed. When answering, the web phone waits up to 6 seconds for a working sound path.
- How to try: answer calls on the web phone from different networks: both sides hear each other.

## 11. Own brand for the web phone (admin)

An admin who sells the web phone under their own name can put two files, `oem.js` and `favicon.ico`, next to the web phone's `index.html`.
Without them, the web phone looks as before. The files must be copied back after each web phone update.

### Own colors

- Where: web
- Before: not available.
- After: the admin can set the main color and the warning, danger and info colors. A wrong value is ignored and the Brekeke color stays.
- How to try: set a blue main color: buttons and headers turn blue.

### Own product name

- Where: web
- Before: not available.
- After: the admin can set a product name. It shows in the browser tab, as the notification title and in the settings text. The admin can also set the name the web phone reports to the phone system.
- How to try: set a name and reload: the tab shows it.

### Skip "Open in app"

- Where: web on a mobile browser
- Before: not available.
- After: the admin can turn off the "OPEN IN APP" question, so phones open the web phone directly.
- How to try: open the web phone on a mobile browser: no question.

### Own notification icon

- Where: web
- Before: not available.
- After: web notifications show the admin's `favicon.ico`.
- How to try: replace the icon, receive a call: the notification shows the new icon.

## 12. Small fixes

### Ringtone list closes on a call

- Where: all
- Before: the ringtone list in settings stayed open when a call came in.
- After: it closes.
- How to try: open the ringtone list, receive a call: the list closes.

### Delete account icon

- Where: Android
- Before: tapping the trash icon next to an account did nothing.
- After: it asks to delete the account.
- How to try: tap the trash icon: the question shows.

### Settings look

- Where: Android
- Before: switches and box labels in settings were slightly out of line.
- After: they line up, as on iPhone.
- How to try: compare the account settings on Android and iPhone.

### "undefined" in error messages

- Where: all
- Before: some error messages had an extra line "undefined".
- After: no such line.

### Sharing the debug log

- Where: Android
- Before: sharing the debug log sent it as a long block of text.
- After: it is sent as a file.
- How to try: Settings → Debug → share the log by mail: a file is attached.

### Fewer crashes

- Where: Android
- Before: the app could crash in some rare cases.
- After: these cases no longer crash.

## Not in 2.18.0

- An "encrypted sign-in link" was built during 2.18 and then removed. It is not in this version.
- The TURN server built into the app (used by the old "TURN" setting) is removed. The app uses only the phone system's TURN server.

## Notes for PM (spec vs app)

- TURN in the link: the spec says the link can set a TURN server, its type, user and password. The app only reads `turn=1` / `turn=0` (see "More settings in the link" and "The TURN setting").
- TURN in account settings: the spec lists TURN SERVER, TURN TRANSPORT, TURN USERNAME and TURN PASSWORD. The app has only "USE TURN AUTOMATICALLY".
- "Set a password": the spec says a button. The app shows it as a hint in the password box.
- "Mailed links now include uc=1" is a phone system change, not an app change.
- Not in the spec: "A link with another phone slot", "A stuck call after hold", "Answering with no connection", "Video call on hold", all of section 7 except the first item, section 8 except the first two items, all of section 11, and section 12 except the first item.

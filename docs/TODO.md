# TODO

Compiled while working on this codebase (the 3.0.0 pnpm/Vite/Tailwind/New-Architecture migration, the `2.17.21` hotfix merge, and the ringtone/DTMF branch merges). Each item points at a real file/behavior found in the current code, not a hypothetical. For the "why is this here" background behind any of these, see the topic docs linked from the root README first -- several items below are one level more actionable than the corresponding topic doc.

## Bugs to fix or verify

- **Android call log write is silently disabled.** `brekekephone/app/src/stores/add-call-history.ts`'s `addToCallLog()` starts with `const disabled = true; if (disabled) { return }` (`// TODO: temporary disabled`). `BrekekeUtils.insertCallLog(...)` is still called from `addCallHistory` on Android but never runs. Either finish whatever blocked this and re-enable it, or remove the dead branch and the now-unnecessary call-log permission if it's not coming back. See [Calling and telephony](./calling-and-telephony.md).
- **`rqLoadings` only guards `hold`/`record`.** `brekekephone/app/src/stores/call.ts` has failure-rollback handlers for transfer/park/conference too, but no double-tap guard for them, and no failure handler for mute at all. Worth auditing whether rapid double-taps on transfer/park/conference/mute can actually desync UI from PBX state, and adding the same `rqLoadings` gating used for hold/record if so.
- **DTMF early-media fix (`sendSipInfoDTMF` in `webrtcclient.js`) was merged from a branch whose own commit message says "Try fix..."** It checks out against the vendored JsSIP internals (`_earlyDialogs`, status constants all verified to exist), but has not been confirmed working against a real PBX/provider that actually plays DTMF from SIP INFO during early media. (A separate copy-paste bug in the same merge -- the `dtmfSendMode===2` `insertDTMF()` call checking `options.duration` instead of `options.interToneGap` for its third argument -- has been fixed.) Still needs a real-device/real-PBX test pass before being trusted in a release.
- **Vietnamese locale asset is a completely empty array, not a finished translation.** `brekekephone/app/src/assets/intl-vi.json` is literally `[]` (0 of 327 entries), and `intl-store.ts` has it commented out. Either populate and enable it (test it, add it to the locale picker) or remove the empty asset so it stops looking like unfinished work.
- **Brand color mismatch between splash screen and in-app theme.** The iOS `LaunchScreen.storyboard` background color and the app's `--primary-500` (`brekekephone/app/src/theme/brekeke.scss` / `brekeke-scss.ts`) are two different shades of green today. Confirm with design whether this is intentional or drift from an old rebrand that only touched one of the two.
- **iOS Xcode project `MARKETING_VERSION` is out of sync with the shipped version.** `BrekekePhone.xcodeproj/project.pbxproj`: the main `BrekekePhone` target has `MARKETING_VERSION = 1.0` (both Debug/Release), while the `BrekekeLPCExtension` target has `MARKETING_VERSION = 3.0.0`. The app currently ships as `3.0.0` only because `Info.plist`'s `CFBundleShortVersionString` is a hardcoded literal instead of `$(MARKETING_VERSION)`. This is a real trap: anyone who "fixes" `MARKETING_VERSION` on the main target expecting it to control the shipped version will get no effect, and anyone who switches `Info.plist` to reference `$(MARKETING_VERSION)` instead of the literal will accidentally ship `1.0`.
- **`dev01/api/index.js` has an unimplemented `// TODO: /dev-api/invoke-plist/:version` endpoint.** The "Invoke Example" builds have a listing endpoint (`/dev-api/invoke-builds`) but no matching iOS install-plist endpoint, unlike dev/prod builds which have `/dev-api/plist/:version`. `dev01/web/src/app/app.tsx` still constructs an `itms-services://` install link for the invoke case regardless, so "Install on iOS" for an invoke-example build currently 404s.
- **`mfa-store.ts`'s `show()` can silently un-set an already-true `skipReconnect` flag.** It does `this.skipReconnect = this.skipReconnect && (opts?.skipReconnect ?? false)` -- if `skipReconnect` was already `true` and a later call to `show()` (e.g. a resend) omits `opts.skipReconnect`, the flag flips back to `false` instead of staying `true`. Worth checking every call site of `show()` passes `skipReconnect` consistently (including resend paths), or fixing the logic to not require every caller to repeat it.
- **`api/pbx.ts`'s `skipProbeOnce` is silently consumed even when it has no effect.** `skipProbeOnce` is only honored when `this.probeVerifiedUri === wsUri` (same-host check), but `this.skipProbeOnce = false` is unconditionally reset right after regardless of whether the URI actually matched. If a caller (currently only `signInByNotification`) ever sets this flag expecting the probe to be skipped but the host differs from what was last probed, the flag is consumed with no effect and won't be available for the next reconnect attempt either. Worth confirming `signInByNotification` always targets the same host it just probed, or making the flag survive until it's actually used.

## Dead code / cleanup

- **LPC's `localSsid` parameter is vestigial on Android.** Threaded through the JS/native call signature (`sync-pn-token.ts` -> `brekeke-utils.ts`) but hardcoded to `''` and never passed to the Android native intent. Either wire it up for real SSID-based gating on Android (to match iOS) or remove the parameter so it stops implying a behavior that doesn't exist. See [LPC subsystem](./lpc.md).
- **`Gemfile.lock` sits at the repo root while `Gemfile` lives in `brekekephone/app/`.** Double check this is intentional Bundler configuration (`brekekephone/app/.bundle/config`'s `BUNDLE_PATH`) and not an accidental side effect of running `bundle install` from the wrong directory once. If intentional, a one-line comment in `docs/ios-build.md` or the Gemfile itself would save the next person from re-investigating this.
- **`make clean`/`make clean_deep` run a bare `pod install --repo-update`, not `bundle exec pod install`.** Everywhere else in the docs (see [iOS build](docs/ios-build.md)) CocoaPods is meant to be Bundler-managed so the pinned `cocoapods`/`activesupport`/`xcodeproj` versions in `brekekephone/app/Gemfile` are actually used. If a developer's global `pod` differs, `make clean` silently reinstalls Pods with the wrong CocoaPods version. Either fix the Makefile to use `bundle exec`, or document that these two targets intentionally bypass Bundler.

## Tooling / process gaps

- **No automated test suite anywhere in the repo.** Still true after the 3.0.0 migration. Pure-logic modules called out repeatedly in these docs as good first candidates (PN payload parsing, resource-line pattern matching, park number encode/decode, the custom-page event queue's dedupe/expiry logic) have zero coverage.
- **No CI configuration in the repo.** Release is entirely the manual `make phone`/`make phonedev`/`make web` process. At minimum, running `pnpm ts`/`pnpm eslint`/`pnpm stylelint` on every PR would catch regressions before they reach `master`.
- **No pre-commit hook enforces format/lint locally.** There is no `husky`/`lint-staged` config anywhere in `package.json` today (a stale, unrelated Husky v4 hook exists in this checkout's `.git/hooks` from a completely different old repo path -- it is not this project's config and doesn't run anything). `pnpm fmt`/`pnpm ts` have to be run manually before a PR; nothing stops an unformatted or type-broken commit from landing.
- **No guard against an automated tool bumping `jssip`/`react-native-webrtc`.** The `.ncurc.js` that used to block this was removed as part of the 3.0.0 migration and nothing replaced it. These two packages must stay in lockstep with the vendored `src/brekekejs/*` SDK; an unattended dependency-update bot would happily propose a breaking bump today.
- **`type-coverage` is informational only (`--at-least 0 --suppressError`), not a hard gate.** The "no `any`" convention has no automated enforcement anymore; it depends entirely on code review.
- **`brekekephone/web` is fully excluded from `pnpm ts`'s `tsc` step.** Both the root `package.json` and `brekekephone/web/package.json` set `"ignoreTsc": true`, and `rntwsc`'s `tsc` runner skips any package with that flag. In practice this means `brekekephone/web` -- a real, shipped package -- gets zero compile-time type checking from `pnpm ts`; only `brekekephone/app` is actually checked. Confirm this is intentional (e.g. web is thin enough that app's checking covers what matters) or fix it.
- **Three real bug-fix branches (`dtmf`, `embed`, `feature/improve-x-ringtone-handling`) sat unmerged for weeks to months before this session found and merged them.** Worth a periodic "list branches not merged into `nam`/`master`, ahead by more than a few commits" check so a real fix doesn't sit stranded again.

## Documentation gaps

- **No `CONTRIBUTING.md`.** Branch naming, commit message conventions, and what a PR is expected to include (manual test matrix, given there's no automated test suite) aren't written down anywhere; they're only inferable from `docs/current-state-and-pr-guidelines.md` and git history.
- **`brekeke.scss` and `brekeke-scss.ts` must be kept in sync by hand.** The file's own comment says so. This is a real ongoing risk (see brand-color item above, which is exactly the kind of drift this setup invites) -- worth at least a `docs/styling-and-ui.md` callout, and ideally a small script/lint check that fails if the two files' values diverge, rather than relying on a code comment.
- **`docs/config-and-build.md` now significantly overlaps `docs/makefile-reference.md` and `docs/credentials-and-config.md`.** Those two were written later and cover the same ground (credentials, version bump locations, Makefile behavior) in more detail. No outright contradiction, but worth trimming `config-and-build.md` down to cross-references only, or merging it away, so there's one source of truth per topic instead of three partially-overlapping ones.

## Nice-to-have improvements

- **`react-native-reanimated` is only a transitive dependency** (pulled in via `rntwsc`'s `react-native-css-animations`), not declared directly in `brekekephone/app/package.json`. Fine for now since nothing imports it directly, but add it explicitly before the first direct usage so it isn't relying on hoisting.
- **Auto-generate one of `brekeke.scss`/`brekeke-scss.ts` from the other** instead of maintaining both by hand, to remove the sync-drift risk at the root instead of just documenting it.

Not urgent, but a future refactor that gives them more distinct names (or consolidates them with an explicit reason parameter) would lower the onboarding cost here.
